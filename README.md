# my_blog_website

Bilingual personal blog: English at `/en/`, Chinese at `/zh/`. Chinese is the
default language, so the repo root `/` redirects to `/zh/`. **Hugo renders
everything** — there is no client-side framework, no hydration step and no
client-side routing. Deployed to GitHub Pages by GitHub Actions.

## Quick start

Requirements: Hugo **extended** >= 0.140, Node >= 22 for the check scripts,
pnpm optional (only used to run the scripts). There are no npm dependencies to
install.

```bash
pnpm dev:hugo
# open http://localhost:1313/zh/ or http://localhost:1313/en/
```

If Hugo is not on `PATH`, put the binary in `.tools/hugo/` or set `HUGO_BIN`.
`scripts/hugo.mjs` resolves all three.

## Verify before pushing

```bash
pnpm check
```

This runs, in order: Hugo build (mirroring `content/` first) → link check over
the output directory → content-mirror check → client-side check (no island or
framework code). CI runs the same command, so a green local run means a green
deploy.

`make check` is a thin wrapper around the same pnpm script.

**Stop `pnpm dev:hugo` before running `pnpm check`.** Hugo's dev server writes
its own (livereload, localhost-based) output into `hugo/public/`; the check
would otherwise inspect development HTML and can race with the server. Or run
`SITE_OUT_DIR=.cache/verify pnpm check` to build elsewhere.

## Bilingual model

- Chinese (`languageCode = "zh-CN"`) lives at `/zh/` and is the default
  language; English (`languageCode = "en-US"`) lives at `/en/`. They are peers;
  Hugo emits the root `/` redirect to `/zh/` automatically.
- **Articles are written once.** Put Markdown in `hugo/content/`; the English
  site renders the same files from `hugo/content-en/`, a mirror generated by
  `scripts/lib/sync-content.mjs` before every Hugo build. Never create
  `.en.md`/`.zh.md` pairs and never edit `hugo/content-en/`.
- Only the site chrome is localized: title, menus, hero copy, descriptions,
  date format, UI strings. An English page therefore shows the article in
  whatever language it was written in.
- UI copy lives in `hugo/i18n/en-US.yaml` and `hugo/i18n/zh-CN.yaml`. The file
  names follow each language's `languageCode`, not its key — Hugo resolves
  translations by language code, so `zh.yaml` is silently ignored.
- Per-language copy (title, description, hero, author bio, date format) lives
  in `[languages.<lang>.params]` in `hugo/hugo.toml`.
- The header language switcher and `<link rel="alternate" hreflang>` tags work
  because both content trees contain the same relative paths; Hugo pairs them
  automatically.
- GitHub Pages only serves a root `404.html`, so `hugo/static/404.html` is a
  bilingual fallback; Hugo still emits per-language 404s under `/en/` and
  `/zh/`.

## Daily AI digest

`scripts/ai_daily.py` builds the digest locally on demand — there is **no
scheduled workflow**. Run:

```bash
pip install -r scripts/requirements.txt
python scripts/ai_daily.py                  # today, Asia/Shanghai
python scripts/ai_daily.py --date 2026-10-20 --force
```

It writes `hugo/content/ai-daily/YYYY-MM-DD.md`; commit and push normally and
the regular deploy workflow publishes it. An existing date is skipped unless
`--force` is passed. Feeds live in the `FEEDS` list at the top of the script,
and links already used in the previous three days are skipped.

The homepage renders the latest digest through
`hugo/layouts/partials/ai-daily.html`: one large card whose inner news list
scrolls independently. Hovering scales the card, and clicking anywhere on it
opens the `/ai-daily/` section.

## Layout

```
hugo/
  hugo.toml             languages, per-language params, menus, shared params
  content/              the articles — written once, in whatever language
  content/ai-daily/     generated daily AI digest (one Markdown per day)
  content-en/           generated mirror of content/ (never edit or commit)
  i18n/                 en-US.yaml / zh-CN.yaml — our UI strings
  layouts/              project templates that override/extend the theme
  assets/css/tokens.css single source of design tokens
  assets/css/main.css   site styles, consumes tokens only
  assets/img/           fingerprinted images used by templates
  static/404.html       bilingual root 404 for GitHub Pages
  themes/blowfish/      vendored theme (v3.9.0), modified in place
scripts/
  hugo.mjs              Hugo wrapper (syncs content, pins caches, runs Hugo)
  dev-hugo.mjs          dev server + content mirror watcher
  lib/sync-content.mjs  content/ -> content-en/ mirror
  ai_daily.py           RSS crawler that generates content/ai-daily/*.md
  requirements.txt      crawler dependencies (feedparser)
  check.mjs             full verification
```

## Site icon and portrait

The favicon and in-page portrait both derive from `assert/img.png` (committed).

```bash
python scripts/make-favicons.py          # favicons -> hugo/static/
```

The portrait is `hugo/assets/img/portrait.png`, rendered next to the homepage
title through Hugo's image pipeline (fingerprinted URL, explicit width/height).
Replace it with the same image whenever the source changes.

## Notes for Windows

`scripts/hugo.mjs` pins Hugo's temp/cache directories under `.cache/` because
the system temp directory is not always writable. No other Windows-specific
setup is required now that the client-side build has been removed.
