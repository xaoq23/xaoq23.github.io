# my_blog_website

Bilingual personal blog: English at `/`, Chinese at `/zh/`. **Hugo owns every
page**; React + TypeScript provides a few isolated interactive islands.
Deployed to GitHub Pages by GitHub Actions.

## Quick start

Requirements: Hugo **extended** >= 0.140, Node >= 22, pnpm 12.

```bash
# one-time: install island dependencies
pnpm --dir islands install

# terminal 1 — Hugo dev server at http://localhost:1313
pnpm dev:hugo

# terminal 2 — rebuild islands on change (writes hugo/static/islands/)
pnpm dev:islands
```

If Hugo is not on `PATH`, put the binary in `.tools/hugo/` or set `HUGO_BIN`.
`scripts/hugo.mjs` resolves all three.

## Verify before pushing

```bash
pnpm check
```

This runs, in order: `tsc --noEmit` → Vite island build → `hugo --minify`
→ link check over `hugo/public/` → translation coverage → island payload
report. CI runs the same command, so a green local run means a green deploy.

`make check` is a thin wrapper around the same pnpm script.

## Bilingual model

- English is the default language at `/`; Chinese lives at `/zh/`
  (language key `zh`, `languageCode = "zh-CN"`).
- Every English content file has a `.zh.md` sibling:
  `about.md` ↔ `about.zh.md`, `posts/.../slug.md` ↔ `posts/.../slug.zh.md`.
  `pnpm check` reports pages that are missing a translation.
- UI copy lives in `hugo/i18n/en-US.yaml` and `hugo/i18n/zh-CN.yaml`. The file
  names follow each language's `languageCode`, not its key — Hugo resolves
  translations by language code, so `zh.yaml` is silently ignored.
- Per-language copy (title, description, hero, author bio, date format) lives
  in `[languages.<lang>.params]` in `hugo/hugo.toml`.
- Homepage bento content is per language in `hugo/data/bento.yaml`; the partial
  picks the current `site.Language.Lang`.
- The header language switcher and `<link rel="alternate" hreflang>` tags come
  from Blowfish and Hugo respectively; they only appear when a page actually
  has a translation.

## Layout

```
hugo/
  hugo.toml             languages, per-language params, menus, shared params
  content/              Markdown (YYYY/MM/slug.md) + .zh.md translations
  i18n/                 en-US.yaml / zh-CN.yaml — our UI strings
  layouts/              project templates that override/extend the theme
  assets/css/tokens.css single source of design tokens
  assets/css/main.css   site styles, consumes tokens only
  data/bento.yaml       homepage bento content, keyed by language
  static/islands/       generated by Vite — never edit or commit
  themes/blowfish/      vendored theme (v3.9.0), modified in place
islands/
  src/entries/          one file per island: <name>.tsx
  src/components/       React components + CSS Modules
  vite.config.ts        outputs to hugo/static/islands/ + manifest.json
scripts/                hugo/islands/check CLI wrappers
```

## How an island is wired

1. Hugo renders a container marked `data-island="<name>"`, including fallback
   HTML that works without JavaScript.
2. `layouts/partials/island-script.html` reads
   `hugo/static/islands/manifest.json` and emits the hashed module script
   (plus its CSS) only on pages that use that island.
3. The Vite entry mounts React on `[data-island="<name>"]` and takes over the
   container. Data travels through `data-*` attributes, including the
   localized label passed as `data-link-label`.

No client-side routing, no global store, no React in article prose, nav or
footer.

## Notes for Windows

`islands/pnpm-workspace.yaml` pins `nodeLinker: hoisted` and
`packageImportMethod: copy`. Without them, pnpm's Windows junctions are not
followed by Node's ESM resolver (so Vite's own dependencies look missing), and
hardlink imports crash the installer on the current Node/pnpm combination. The
settings are harmless on Linux and CI.
